# 05 · bfcache in Next.js

Next.js 앱에서 뒤로 가기를 누르면 언제 bfcache가 일하고 언제 안 하는지 눈으로 봐요. 채용 공고 20개 목록은 브라우저가 API를 불러 그리고(CSR, TanStack Query), 공고 상세는 서버가 API를 불러 그려요(SSR).

```sh
# bfcache는 운영 모드에서만 보여요. 빌드한 결과로 확인해요.
pnpm --filter 05-performance-next.js build
pnpm --filter 05-performance-next.js start   # http://localhost:5115

# 코드를 고치면서 볼 때는 (이때는 얼려 두지 않아요)
pnpm --filter 05-performance-next.js dev     # https://localhost:5115
```

## 결론부터 말할게요

- **Next.js에서도 bfcache는 저절로 일해요.** 따로 짤 코드는 없어요.
- **다만 문서가 바뀔 때만이에요.** 목록에서 `<Link>`로 상세에 갔다가 뒤로 오는 건 문서가 그대로라 bfcache가 아니에요. Next.js가 목록 화면을 처음부터 다시 그려요.
- **앱 안에서 뒤로 올 때 보던 자리를 지키는 건 TanStack Query 몫이에요.** 받아 둔 목록으로 바로 그려야 브라우저가 스크롤 위치를 되돌려요.
- **얼려 둔 화면은 떠날 때 값 그대로예요.** 낙관적 업데이트로 켠 좋아요도 그대로 남아요. 다만 떠난 사이 다른 탭에서 바뀐 값은 몰라서, 꺼내질 때 서버에 다시 물어요.
- **외부 사이트에 다녀올 때 효과가 커요.** 목록은 받아 둔 그대로, 상세는 서버가 그린 그대로 나와요. API도 SSR도 다시 하지 않아요.
- **SSR 페이지의 `no-store`는 크롬에서 막는 원인이 아니에요.** 쿠키가 바뀌었을 때만 다시 불러와요.

## 직접 해보기

화면마다 큰 숫자 하나만 보면 돼요. 목록은 **목록 API를 부른 횟수**, 상세는 **서버가 그린 시각**이에요. 아래 "지금 문서" 카드의 **문서를 연 시각**이 그대로면 같은 문서예요.

| 이렇게 해 봐요 | bfcache | 이렇게 보여요 |
| --- | --- | --- |
| 목록을 내려 공고 누르기 → 브라우저 뒤로 가기 | 아니에요 | 보던 자리 그대로예요. 1분 안에 돌아오면 API 횟수도 그대로예요. 문서를 연 시각도 그대로예요 |
| 위와 같은데 상세에서 1분 넘게 있다가 뒤로 가기 | 아니에요 | 보던 자리 그대로 목록을 먼저 보여주고, 뒤에서 새로 받아서 API 횟수가 1 늘어요 |
| 목록에서 "다른 사이트에 갔다가 돌아오기" → "원래 화면으로 돌아가기" | ✅ | API 횟수가 그대로예요. "얼려 둔 화면을 그대로 꺼냈어요"가 나와요 |
| 상세 주소를 새로고침 → "회사 홈페이지에 갔다가 돌아오기" → "원래 화면으로 돌아가기" | ✅ | 서버가 그린 시각이 그대로예요. `no-store`가 붙어 있어도 꺼내요 |
| 위와 같은데 "로그아웃한 것처럼 쿠키를 바꾸고 돌아가기" | ❌ | 서버가 다시 그려서 시각이 바뀌어요. 막힌 이유(`response-cache-control-no-store`)도 보여줘요 |
| `pnpm dev`로 띄워서 아무거나 | ❌ | 개발 서버가 붙이는 `no-store`와 WebSocket 연결 때문에 얼려 두지 않아요 |

크롬 157과 Next.js 16.4.5에서 확인했어요. 사파리와 파이어폭스는 확인하지 않았어요.

## 앱 안에서 뒤로 올 때 스크롤 위치 지키기

앱 안에서 뒤로 오면 Next.js가 목록 화면을 처음부터 다시 그려요. 브라우저는 그 순간 페이지 길이만큼만 스크롤을 되돌릴 수 있어요. 목록이 없고 '불러오는 중'만 있으면 페이지가 짧아서 보던 자리를 잃어요.

그래서 받아 둔 목록으로 바로 그려요. `src/app/page.tsx`에서 `useQuery`에 두 가지를 줬어요.

| 옵션 | 값 | 하는 일 |
| --- | --- | --- |
| `staleTime` | 1분 | 받은 지 1분 안에는 그대로 믿고 다시 부르지 않아요. 지나면 받아 둔 목록을 먼저 그리고 뒤에서 새로 받아요 |
| `gcTime` | 5분 | 목록 화면이 사라진 뒤에도 받아 둔 목록을 5분 동안 남겨 둬요. 지나면 '불러오는 중'부터 다시 시작해서 보던 자리를 잃어요 |

스크롤을 되돌리는 코드는 따로 없어요. 목록이 바로 그려지면 브라우저가 알아서 되돌려요. 크롬 157에서 14번째 공고까지 내렸다가 상세에 갔다 뒤로 와서 `scrollY`를 재 봤어요.

| 목록을 받는 방법 | 떠날 때 | 뒤로 온 직후 | 1.5초 뒤 | 목록 API |
| --- | --- | --- | --- | --- |
| `useEffect`에서 `fetch` | 1022 | 178 | 178 | 한 번 더 불러요 |
| TanStack Query (`staleTime` 1분, `gcTime` 5분) | 1022 | 1022 | 1022 | 다시 부르지 않아요 |

## 좋아요(낙관적 업데이트)와 bfcache

공고 상세의 좋아요는 TanStack Query `useMutation`으로 서버 답을 기다리지 않고 아이콘부터 켜요. 실패하면 되돌려요. 서버는 저장을 바로 하고 0.7초 늦게 답해요.

| 이렇게 해 봐요 | bfcache | 이렇게 보여요 |
| --- | --- | --- |
| 좋아요 → 저장 끝난 뒤 "회사 홈페이지에 갔다가 돌아오기" → "원래 화면으로 돌아가기" | ✅ | 켜진 아이콘이 그대로예요. 서버에 다시 물어봐도 같아서 그대로 둬요 |
| 좋아요 누르자마자 "회사 홈페이지에 갔다가 돌아오기" (서버 답이 오기 전) | ✅ | 요청이 끝나지 않았어도 크롬은 얼려 뒀어요. 서버에도 저장됐어요 |
| 좋아요 → "회사 홈페이지에 갔다가 돌아오기" → "다른 탭에서 좋아요를 바꾸고 돌아가기" | ✅ | 떠날 때 값(켜짐)을 잠깐 보여주고, 서버에 다시 물어서 꺼진 값으로 고쳐요 |
| 좋아요 → "회사 홈페이지에 갔다가 돌아오기" → "로그아웃한 것처럼 쿠키를 바꾸고 돌아가기" | ❌ | 서버가 다시 그려요. 서버에 저장돼 있어서 켜진 채로 나와요 |

- bfcache는 JavaScript 메모리까지 얼려 둬요. 그래서 TanStack Query 캐시에 있는 좋아요 값도 떠날 때 그대로예요.
- 좋아요는 `staleTime: Infinity`로 뒀어요. 서버가 그려 준 값으로 시작하고, 바뀌는 건 내가 누를 때뿐이라서요. 그래서 꺼내질 때 TanStack Query가 알아서 다시 묻지 않아요. 돌아올 때 `visibilitychange`는 오지만, 신선하다고 보는 값은 다시 받지 않아요.
- 그래서 `pageshow`의 `persisted`가 `true`일 때 `invalidateQueries`로 좋아요만 다시 받아요. 서버가 그린 공고 내용과 시각은 그대로 둬요.

## 만들며 알게 된 것

- Next.js는 요청마다 새로 그리는 페이지에 `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`를 붙여요. 미리 그려 둔 목록과 외부 사이트 페이지에는 붙이지 않아요.
- 목록에서 `<Link>`로 상세에 갔다가 외부 사이트에 다녀와도 bfcache로 꺼내요. 이때 문서는 목록 것이라 `no-store`가 없어서, 쿠키를 바꿔도 그대로 꺼내요.
- Next.js 16의 `cacheComponents`도 떠난 화면을 지우지 않고 숨겨 뒀다가 '불러오는 중' 없이 보여줬어요. 다만 `useEffect`가 다시 돌아서 API는 한 번 더 불러요. 이 샘플에서는 켜지 않았어요.
- 개발 서버는 HTTPS라서, 서버가 자기 API를 부를 때 mkcert 인증서를 믿도록 `NODE_OPTIONS=--use-system-ca`를 붙여요.
- 화면 틀은 다른 샘플과 같은 `shared/ui.tsx`를 써요. 그 안에서 `createContext`를 불러서, 서버 컴포넌트가 아니라 `'use client'` 파일에서만 가져와요.
